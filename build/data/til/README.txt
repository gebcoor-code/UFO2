UFO2.TIL - цвета тайлов локаций (нужен только Python 3)

Что где лежит
  XMnn_tiles.png  - наборы тайлов: их и раскрашивают. Сверху - 16 цветов палитры этой локации (PALETTE.txt) с номерами и справа от них
                    два серых: NO DOT (#606060) и TRANSPARENT (#282828) - всё удобно брать пипеткой, ниже - тайлы набора по одному, 1:1 (точка тайла = пиксель), по 16 в ряд, над каждым
                    его номер - место в наборе (0, 1, 2.. по порядку). Цвета клетки:
                      любой из 16 цветов палитры - точка тайла этого цвета (чёрный - чёрный);
                      тёмно-серый (40, 40, 40; или ярко-синий 9) - точка тайла "нет цвета": прозрачная, видно то, что
                        под ней (с 0.56.0);
                      серый #606060 (96, 96, 96) - не тайл: точки у тайла здесь нет (с 0.57.0). Закрасил такую точку
                        любым из 16 цветов - она добавится к тайлу; закрасил точку тайла серым #606060 - она
                        уберётся из тайла. Форма тайла меняется в игре: UFO2.TIL несёт
                        правки формы, игра 0.57.0 и новее накладывает их при загрузке локации (и пересчитывает высоту
                        тайла - по ней игра решает, что тайл заслоняет). Старые версии игры правки формы не видят.
                    Под тайлом мелко "NOT USED" - пустышка: такого тайла нет в игре (ни в одном её наборе,
                    src/xmgame.bin), он нигде не используется - ни на картах, ни в UFO2.TIL (mktil.py его
                    пропускает); красить его незачем. Обычно это чуть другая копия настоящего тайла из другого
                    набора (XM06 62 - якорь, настоящий - XM08 42).
  maps/           - карты локаций, собранные с этими цветами (python mkmap.py all): по одной на локацию X00..X11
                    (вариант A), у морского дна - все 8 вариантов: x00 (A, XM02), x00b (B, XM03), x00c (C, XM14),
                    x00d..x00h (D..H, XM16..XM20):
    x<nn>.png     - карта целиком (если есть 2-й этаж: слева 1-й, справа 1-й со 2-м поверх);
    x<nn>_map.png - все тайлы этой карты по одному, 1:1 (сверху палитра, как в наборах). Над тайлом крупно - его
                    номер в карте (id тайла в игре, 0..95; на карте стоят не все тайлы, отсюда пропуски). Под ним
                    мелко - откуда берутся его цвета: набор и место в нём ("04 9" = XM04_tiles.png, тайл 9).
                    Этот лист можно править прямо так (удобно смотреть тайлы одной карты вместе): mkmap.py all
                    перенесёт правки в наборы - каждый тайл в тот набор и на то место, что подписаны под ним.
    MAPS.txt      - то же списком по всем картам.
    _orig/        - листы карт как их записал mkmap.py all (по ним видно, что в листах поправлено) - не править.
  full_maps/      - (с 0.65.3) полные карты (python mkmap.py full): все варианты всех локаций (x01a..x01d, x07a..d,
                    x08a..d, x11a..d, x00a..h; у кусочных - 16 кусков по порядку, все есть), куски корабля игрока и
                    НЛО (xl0, xl1 - игра ставит их в начале боя). Любой тайл, который есть в картах игры, есть здесь.
                    FULL.txt - список карт и тайлы наборов, которых нет ни на одной карте: их игра ставит во время
                    боя сама (открытая дверь, обломки) или не ставит вовсе (пустышки NOT USED - не в счёт).
  PALETTE.txt     - (0.66.0) палитры локаций - см. "Палитра локации"; PALETTE_AUDIT.txt, PALETTES.png - их разбор.
  UFO2.TIL        - результат mktil.py: кладётся рядом с UFO2.COM.
  src/            - оригиналы, не править:
    XMnn.png      - тайлы игры как в игре: на каждый ряд тайлов две полосы, верхняя - исходные цвета (здесь не
                    используются), нижняя - исходная форма: тёмно-серый - точки нет, чёрный - "бумага", белый -
                    "чернила", светло-серый - бит чернил вне маски. По ней скрипты узнают тайл игры (форму правят в
                    листах наборов - см. выше, не здесь).
    xmgame.bin, XL*.LND - тайлы игры и карты локаций (для mkmap.py).

Сборка (всё пишется поверх, без вопросов; что записано - видно в консоли: "overwritten:" - файл был и
перезаписан, "written:" - новый. Файл, который вышел бы таким же, как есть, не трогается и не пишется - так видно,
что на самом деле поменялось)
  python mktil.py        - UFO2.TIL из XMnn_tiles.png (и форм src/XMnn.png).
  python mkmap.py all    - 1) правки листов maps/x<nn>_map.png -> в наборы XMnn_tiles.png (листы без правок ничего
                            не меняют; если одну точку по-разному поправили в двух листах - берётся лист с большим
                            номером, скрипт об этом пишет; форма тайла - тоже: серый #606060 - не тайл);
                            2) заново все карты в maps (вариант A каждой), листы их тайлов и MAPS.txt.
                            Обычный порядок: правишь XMnn_tiles.png и/или maps/x<nn>_map.png -> mkmap.py all ->
                            mktil.py. Править можно и наборы, и листы карт одновременно: правкой листа считается
                            только то, что в нём изменено с прошлой сборки (её копия - maps/_orig, не трогать).
  python mkmap.py full   - полные карты в full_maps/ (и FULL.txt); после правок наборов - заново (около минуты)
  python mkmap.py apply maps/x03_map.png - только перенести правки одного листа (или папки) в наборы, без сборки карт
  python mkmap.py x04    - одна карта (отладочной локации 04: остров) -> x04.png рядом со скриптом
  python mkmap.py x07c   - локация 07 (база I), вариант C (где игра выбирает вариант случайно; по умолчанию A)
  python mkmap.py xl11 out.png - карта файла XL11.LND (городской порт) в out.png
  python mkmap.py x02 -s 5     - части карты перемешаны, как это делает игра (случайно, с номером 5)
  python mkmap.py x01 -t       - и ещё x01_map.png: тайлы этой карты
  (листы читает и рисует tilsheet.py - он должен лежать рядом)

  Стык с полом (с 0.59.0): в клетке карты стоит один тайл, пол под предметом - часть самого тайла. Если тайл стоит
  на разной земле (один набор предметов у разных локаций), низ тайла можно сделать прозрачным (TRANSPARENT): точки
  тайла цвета "нет" в строках 16..31 игра и mkmap.py закрашивают полом этой локации - самым частым тайлом 1-го
  этажа карты. NO DOT так не заполняется (предметы 2-го этажа висят в воздухе - им пол не нужен), прозрачное выше
  16-й строки - тоже (окна, просветы). Пол один на локацию: где пол разный (порт: асфальт и палуба), будет самый
  частый.
  Корабль игрока (XM00, тайлы 3..15) стоит в клетках поля вместо пола: игра (с 0.58.0) и mkmap.py рисуют под его
  тайлами пол локации (самый частый тайл карты) - там, где у тайла прозрачно или нет точки (строки 16..31).
  Xnn - номера как у UFO2 DEBUG Xnn (LOC GO): 00 морское дно (варианты A..H: XL2, 3, 14, 16..20), 01 корабль I
  (XL6A..D), 02 порт городской (XL11), 03 порт другой (XL4), 04 остров (XL9), 05 наша база (XL7), 06 колония I
  (XL15), 07 база I (XL5A..D), 08 Тлет (XL10A..D), 09 колония II (XL13), 10 база II (XL12), 11 корабль II (XL8A..D).
  x11 и xl11 - разное: x11 - локация 11 (корабль II, XL8A), xl11 - файл XL11.LND (городской порт, x02).
  На картах не рисуются корабль игрока и НЛО (их игра ставит в начале боя), бойцы и пришельцы. Карты морского дна,
  колоний и др. игра собирает из 16 кусков в случайном порядке - по умолчанию куски по порядку, -s N - перемешаны
  (похоже на игру, но не точно как она).

Палитра локации (с 0.66.0 - своя у каждой локации)
  На экране боя 16 цветов из 64 цветов ATM (R, G, B - по 0, 96, 192, 255). Каждая локация (её набор XM02..XM20)
  теперь со своей палитрой - PALETTE.txt: строка "XMnn" и 16 цветов слотов 0..15 по три цифры R G B, каждая 0..3
  (000 чёрный, 222 серый, 133 светло-голубой...). Палитра набора видна полосой сверху его листа, в листах карт,
  на картах maps/ и full_maps/ - всё рисуется и читается в палитре своей локации.
  Слоты 0, 1, 2, 6, 7, 9, 10, 12, 13, 14, 15 - общие для всех локаций: ими нарисованы панель, значки, текст,
  выстрелы, взрывы, курсор, наши бойцы не в фокусе - их в PALETTE.txt не изменить (скрипт оставит как есть и
  скажет). Слоты 3, 4, 5, 8, 11 (бордовый, серо-зелёный, розовый, коричневый, зелёный) - локации. Слот бумаги поля
  (голубая 5 - XM02, XM05, XM15, XM16; зелёная 4 - XM09, XM19) - цвет Спектрума (окна игры над полем), тоже не
  меняется. Бойцы и пришельцы рисуются через те же слоты: если локация взяла слот под свой цвет, их точки этого
  цвета берут ближайший из остальных (зелёный -> серо-зелёный, коричневый -> оливковый...) - на какой, видно в
  PALETTES.png справа и в PALETTE_AUDIT.txt ("спрайты здесь"). Розовый и бордовый (наши бойцы) остаются везде.
  Тайл, нарисованный цветом слота, в каждой локации показывается цветом этого слота в её палитре (один тайл у разных
  локаций - см. ниже). Свой цвет локации в листе - рамкой в PALETTES.png; пипеткой его берут из полосы листа.
  Листы, нарисованные до 0.66.0 (старой палитрой), читаются как прежде: цвет старой палитры - его слот.

  python mkpal.py      - разбор: PALETTE_AUDIT.txt (по каждой локации - сколько % точек тайлов каждого слота, кто
                          ещё его использует, куда уходят цвета спрайтов) и PALETTES.png (палитры всех локаций рядом,
                          под цветом - % тайлов, справа - цвета спрайтов на этой локации). Около минуты.
  python mkpal.py new  - предложить палитры заново (старый PALETTE.txt -> PALETTE_old.txt): из слотов 4, 8, 11 те,
                          что тайлы локации почти не используют (меньше 0.2% точек), получают новый цвет - оттенок
                          основных цветов этой локации, которого в палитре ещё нет (не ближе 80 к остальным). Им и
                          рисовать новые детали. Слоты, которые тайлы локации используют, остаются как были.
  После правки PALETTE.txt: python mkmap.py all (полосы палитры, карты), python mktil.py (палитры - в UFO2.TIL;
  игре до 0.66.0 они не нужны и не мешают; игра 0.66.0 с UFO2.TIL без палитр - палитра боя как раньше).
  XM00, XM01, XMMORE (корабль игрока, НЛО, общие тайлы) рисуются в обычной палитре боя - на локации их тайлы
  показываются её палитрой (они используют только общие слоты и бордовый).

Один тайл в нескольких наборах
  Один и тот же тайл игры встречается в разных наборах (и у разных локаций). Игра берёт цвета из первой
  раскрашенной его копии по порядку XM00..XM20, XMMORE - поэтому тайл карты иногда красится из набора другой
  локации (это видно под тайлом в x<nn>_map.png и в MAPS.txt), и правка цвета меняет его во всех локациях.
  mktil.py пишет, сколько таких тайлов раскрашено по-разному ("N tiles coloured differently...") - это не ошибка:
  остальные копии просто не используются. И сколько пустышек пропущено ("N dummies ... left out").

Как устроен UFO2.TIL
  UFO2.DAT - тайлы игры в ZX-виде (маска + чернила): их загружает игра для каждой локации. UFO2.TIL - для каждого
  тайла только хеш его 128 байт (3 байта: по нему игра находит цвета своего тайла) и цвета. Цвета сжаты с опорой
  на биты игры: два текущих цвета - для точек-"бумаги" и для точек-"чернил", записываются только смены (байт на
  смену). Цвет у точки любой, но файл тем меньше, чем реже цвет меняется по ходу строки внутри своего класса.
  Место под цвета ограничено: mktil.py пишет, сколько свободно (это размер цветов до сжатия). UFO2.TIL сжат
  (начинается с "PK"); от версий до 0.54.9 игра его не берёт - соберите заново этим mktil.py.
  Правки формы (0.57.0): таблица после индекса - у каких тайлов какие байты (маска / чернила) заменить; mktil.py
  пишет, у скольких тайлов форма изменена. Добавленная точка - "чернила" (чёрная - "бумага"). Тайлы игры в UFO2.DAT
  не меняются: правки накладывает игра, когда разворачивает тайлы локации в цвет.
